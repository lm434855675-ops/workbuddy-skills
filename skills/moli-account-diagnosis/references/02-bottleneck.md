# 02 · 诊断树：主卡点定位流程

## 定位原则

**一次只打一个七寸。** 诊断的产出不是问题清单，是"下一个阶段只解决什么"。
并列多个主卡点 = 没定位，用户拿到也不知道先干哪个。

## 诊断树（按顺序走）

```
Q1 有没有人进来？(traffic ≤ 5)
├─ 没有 → 主卡点 = 流量结构
│        次级观察：转化/产品是否是"没流量也成立"的问题
└─ 有 → Q2

Q2 进来的人付不付钱？(conversion ≤ 5)
├─ 不付 → 主卡点 = 转化链路
│        检查序：承接话术 → 价格/门槛 → 信任背书 → 成交路径长度
└─ 付 → Q3

Q3 付完还来不来、带不带人？(ops ≤ 5 或 product ≤ 5)
├─ 不来 → 按弱项二选一：
│        product 更弱 → 主卡点 = 货盘结构（无复购设计）
│        ops 更弱 → 主卡点 = 运营节律（有货无触达）
└─ 来 → Q4

Q4 想放大放得动吗？(org ≤ 5)
├─ 放不动 → 主卡点 = 组织执行（老板即天花板）
└─ 放得动 → 无单点卡点，出增长优先级（下一阶段增量在哪）
```

## 卡点链常识（15 年陪跑经验）

- **流量差的常见真相是转化差**：承接链路漏损大到投多少亏多少时，先修链路再买量。
- **转化差的常见真相是货盘差**：价格带与人群错位时，话术和页面都救不回来。
- **复购差的常见真相是运营节律差**：不是产品不行，是买完没人理。
- **放大难的常见真相是组织差**：全案项目里甲方团队接不住，方案再好落地打折。
- **崩盘项目复活的第一步从不是加功能**，是重新定位——砍掉失血动作，集中打一个能回款的点。

## 主卡点报告格式

```
主卡点：<维度名>
判定依据：<用户给的事实 + 对应评分>
下一步只解决：<一句话>
旁支观察（不动）：<列表，标注"当前阶段让位">
```
