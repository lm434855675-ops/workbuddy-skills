# 03 · 报告结构 + 优先级矩阵用法

## 报告结构（Markdown，固定七段）

1. **一句话总评**：加权总分 + 红灯/黄灯/绿灯 + 当前阶段一句话定性。
2. **五维评分卡**：表格（维度/得分/权重/依据/灯色），总分由 `scripts/score.py` 计算。
3. **主卡点**：见 [02-bottleneck.md](02-bottleneck.md) 的格式。
4. **分维观察**：每维 2-3 条事实观察，非主卡点维度只观察不开方。
5. **Top 3 改进动作**：按「影响 × 难度」矩阵排，每条带 owner 建议 + 判定标准。
6. **待补数据清单**：缺什么数、去哪取、取到后 revise 哪个维度。
7. **免责与边界**：诊断基于用户提供信息，未核验原始数据；建议方向不构成结果承诺。

## 优先级矩阵（Top 3 动作排序用）

| | 低难度 | 高难度 |
|---|---|---|
| **高影响** | 第 1 优先（立即做） | 第 2 优先（规划做，拆里程碑） |
| **低影响** | 第 3 优先（顺手做） | 不做（本阶段） |

- 高影响高难度的动作必须拆出**第一个 30 天能完成的子动作**再进 Top 3。
- 每条动作的判定标准写法：数字（"承接话术 A/B 后咨询转化率从 3% 到 6%"）或状态（"三层货盘价表明世上线"）。

## 交付规范

- 报告为 Markdown，快拆 3 分钟内可读完；超过一页纸的诊断是方案不是快拆。
- 数据缺失处在报告中标「待补」，禁止脑补填充。
- 用户只要评分卡时，可单独交付 score.py 的 JSON 输出。

## 红线

- 禁止出现"保证/必涨/稳赚"类表述。
- 禁止把行业默认假设写成用户事实（假设必须标注）。
- 禁止替用户承诺 ROI。
