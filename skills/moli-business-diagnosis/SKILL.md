# 商业模式诊断

帮你把一个生意的顶层逻辑拆成**五段链：定位 → 价值 → 变现 → 增长 → 壁垒**，逐段找断点。
与「账号快拆诊断」的分工：那个看**运营五维**（流量/转化/货盘/运营/组织，偏执行层），本技能看**顶层逻辑**（模式成不成立，偏决策层）。

## 第一步：信息收集

| 字段 | 含义 | 必填 |
|---|---|---|
| 生意一句话 | 卖什么给谁解决什么问题 | 必填 |
| 变现方式 | 怎么收钱、客单多少 | 必填 |
| 当前状态 | 0-1 / 1-100 / 下滑 / 盘活 | 必填 |
| 核心资源 | 团队/供应链/渠道/品牌，有什么 | 必填 |
| 卡点 | 用户自己觉得哪里不对 | 选填 |

**最多问一轮，答不上标「待补」+默认假设。**

## 第二步：五段链体检

读 [references/01-five-links.md](references/01-five-links.md)，逐段过检查项：

| 段 | 一句话检查 | 断点信号 |
|---|---|---|
| 定位 | 卖给谁、不卖给谁，说得清吗 | "什么人都能买"=没定位 |
| 价值 | 客户为什么选你不选别家 | 只能说"更便宜/更好"=无差异价值 |
| 变现 | 收钱路径短且毛利撑得住模式吗 | 变现链路长或毛利<30% |
| 增长 | 增量从哪来，可复制吗 | 增长靠老板人脉/单一渠道 |
| 壁垒 | 别人抄你需要多少成本 | 无壁垒+高利润=被抄倒计时 |

## 第三步：断点定位与修复优先级

读 [references/02-break-fix.md](references/02-break-fix.md)：

- **只定一个主断点**：五段链是串联的，最上游的断点优先修。
- 修复动作按「影响 × 难度」排序，每条带判定标准。
- 崩盘救援项目：先砍失血动作，再谈修复顺序。

## 第四步：产出报告

固定六段：① 一句话总评（模式成不成立）② 五段链体检表 ③ 主断点与修复优先级 ④ 旁支观察 ⑤ 待补数据清单 ⑥ 免责与边界。

**渲染成自包含 HTML**（深浅色自适应、可打印）：把六段组织成 spec.json 后跑

```bash
python3 scripts/build_report.py --spec report.json --out 商业模式诊断报告.html
```

承载型区块（tiles/steps/timeline/gantt/checklist/table/bars/stack/funnel）至少一种；timeline 每个动作必须带 criterion（判定标准）；区块数 ≥8、正文 ≥1500 字符（诊断类快速回答才可 `--allow-thin`）。

## 退出码处理

| 脚本 | 码 | 含义 | 处理 |
|---|---|---|---|
| chain_check.py | 0 | 成功 | 用输出：总评/主断点/旁支断点 |
| | 1 | 参数错误 | 检查 `--scores` JSON 键为五段英文名（positioning/value/monetization/growth/moat） |
| | 9 | JSON 解析失败 | 修正 JSON 格式后重跑 |

## 全局硬规则

| 项 | 要求 |
|---|---|
| 只定一个主断点 | 并列多个=没定位 |
| 依据先于结论 | 每段判定附用户给出的事实 |
| 待补不脑补 | 缺数据标「待补」+默认假设并显式标注 |
| 崩盘先止血 | 救援项目第一动作是砍失血项，不是加增长 |
| 不代做决策 | 诊断给方向与优先级，不替用户拍板 |
| 不承诺结果 | 禁"按此调整必成"表述 |

## 常见反模式：看到就纠正

- **"我的产品所有人都能用"** → 没定位=没定价权；先选一个最愿意付钱的窄人群。
- **"我们比竞品质量好"** → 质量是入场券不是差异；找客户感知得到的差异点。
- **"先做大规模再想变现"** → 变现链路长的模式，规模越大亏越多。
- **"增长靠投流"** → 投流是放大器不是增长引擎；先确认留存与复购。
- **"我们没有壁垒但利润高"** → 高利润无壁垒是抄你的请柬；先建壁垒再放大。
- **"多方位同时优化"** → 串联链只修最上游断点，同时修五段=五段都修不动。
