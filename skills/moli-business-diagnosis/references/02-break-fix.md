# 02 · 断点定位决策树 + 崩盘救援原则

## 断点定位决策树（按序走，定一个主断点）

```
Q1 定位说得清吗？(定位段 ≤5)
├─ 说不清 → 主断点 = 定位（人群/边界/价格带）
└─ 说得清 → Q2

Q2 客户有非选你不可的理由吗？(价值段 ≤5)
├─ 没有 → 主断点 = 价值（差异点不可感知）
└─ 有 → Q3

Q3 收钱路径短、毛利撑得住吗？(变现段 ≤5)
├─ 不能 → 主断点 = 变现（路径长或毛利结构不成立）
└─ 能 → Q4

Q4 增量可复制吗？(增长段 ≤5)
├─ 不可复制 → 主断点 = 增长（依赖人脉/单一渠道）
└─ 可复制 → Q5

Q5 别人抄你有多难？(壁垒段 ≤5)
├─ 太容易 → 主断点 = 壁垒（先建壁垒再放大）
└─ 不难 → 无单点断点，出增长优先级
```

## 修复优先级矩阵

| | 低难度 | 高难度 |
|---|---|---|
| **高影响** | 立即做 | 规划做（拆 30 天子动作） |
| **低影响** | 顺手做 | 不做 |

## 崩盘救援三原则（盘活项目专用）

1. **先止血再谈增长**：第一周砍掉所有失血动作（亏损投放/无效库存/失血渠道），不是先加增长动作。
2. **重新定位先于方案**：多数崩盘是定位漂移，不是执行不力。
3. **单点回款验证**：集中全部资源打一个能回款的点，用 30-60 天验证，不分散突围。

## 主断点报告格式

```
主断点：<段名>
判定依据：<用户事实 + 段评分>
修复方向：<一句话>
30天子动作：<可验证的第一个动作>
旁支观察（不动）：<列表>
```

## 实证锚点（作者履历）

"接手过多个濒临崩盘的项目从 0 开始重新战略定位、制定可落地方案陪跑至复活"——
救援项目的共同起点：**先定位，再止血，后单点回款**。跳过顺序的救援都是二次崩盘。
