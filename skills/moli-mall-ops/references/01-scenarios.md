# 01 · 场景路由：首页 / 分类 / 会员日

## 首页装修

**判定要素**：用户说"改版/没人点/Banner/楼层/首屏"任一即命中。

**流程**：取数（楼层曝光/点击/引导 GMV）→ 诊断（mall_calc.py floor）→ 定顺序 → 改一版 → 观察 7 天 → 固化/回滚。

**首屏三层法则**：身份入口 → 主 KV → 券/核心玩法。超过三层的首屏等于没有首屏。

**坑位 UV 价值排序**：楼层顺序按"引导 GMV / 曝光 UV"排，不按 CTR、不按老板喜好。CTR 高但 UV 价值低的楼层（如纯形象 Banner）下沉。

## 分类导航

**判定要素**：用户说"分类/类目/导航/搜索/商品分组"任一即命中。

**前台分类 ≠ 后台类目**：前台是买手思维（用户怎么逛），后台是货盘思维（怎么管）。类目树按前台搭。

**三级封顶**：一级 ≤ 8 个，每组 ≥ 6 个在售 SKU；更深的做成筛选项（价格带/规格/场景），不做四级类目。

**搜索词反哺**：近 30 天搜索词 Top 100 里有前台类目不承接的词 → 新增类目或调整命名。

## 会员日

**判定要素**：用户说"会员日/权益/发券/储值/唤醒沉睡"任一即命中。

**四段式**：蓄水 → 预热 → 爆发 → 返场复盘。

**四个权益杠杆**（按"只有会员能拿到"设计，逐条与老板确认）：
1. 专属价（划线价须真实成交过并留存举证）
2. 专属货（会员日限定组合/小样）
3. 专属额度（如会员日双倍积分）
4. 专属服务（如会员优先发货/专属客服通道）

**触达矩阵**（按成本从低到高）：订阅消息 → 企微/导购 → 站内 Push → 短信。短信永远最后，且必须有签名+退订、正文 ≤70 字、避开 21:00–08:00。

**分层发券**：至少三档（高价值/中价值/沉睡），同一张券发给所有会员 = 给高价值会员白白打折。

**增量口径**：会员日增量 = 活动 GMV − 平日日均 GMV × 活动天数。不扣基线的"涨 3 倍"不可信。

## 平台基线（不锁死菜单）

有赞 / 微盟 / 自建小程序三类的能力差异集中在：会员体系深度、分销合规配置、营销工具丰富度。
写方案时按能力维度描述（"需要支持分层发券的券系统"），不写"在 XX 菜单第几层"——菜单路径随版本变，
让用户在后台搜组件名确认，方案里附一句"以当前版本后台为准"。
